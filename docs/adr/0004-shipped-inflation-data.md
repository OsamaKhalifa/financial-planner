# ADR-0004 — Shipped yearly inflation defaults

**Status:** proposed · 2026-10-16 · architect · World Bank endpoint verified 2026-10-16

## Decision

Ship one asset, `assets/inflation/cpi_annual.json`, generated by `tool/gen_inflation.dart` from the **World Bank WDI indicator FP.CPI.TOTL.ZG** for the countries of the v1 unit and market lists **plus the euro area (World Bank aggregate `EMU`)**; user overrides live in the Drift table `inflation_overrides` and always win.

### Source (verified)

```
GET https://api.worldbank.org/v2/country/{ISO3;ISO3;...}/indicator/FP.CPI.TOTL.ZG?format=json&date=2000:{lastYear}&per_page=20000
```

Response: `[ {page, pages, per_page, total, sourceid, lastupdated}, [ {country:{id,value}, countryiso3code, date:"2025", value: 14.07 | null, ...}, ... ] ]`. On 2026-10-16: `lastupdated = 2026-10-08`; Egypt 2025 = 14.07, Saudi Arabia 2.04, euro area (`EMU`) 2.47, US 2025 = `null`, Qatar 2025 = `null`. Keyless, CC BY 4.0 (World Bank open data terms) → attribution string kept in the asset and shown in S8/S9.

The euro area is in the same dataset (`EMU`), so **Eurostat HICP is not needed** — one source, one script, one attribution.

### Countries

Derived in the script from `lib/core/reference/` (no second list): every country that a v1 currency maps to (spec §2.1) and every market's country. v1 = 29 currencies → 28 countries + `EMU`: ARE, AUS, BGD, BHR, CAN, CHE, CHN, DZA, EGY, EMU, GBR, HKG, IDN, IND, JOR, JPN, KWT, MAR, MYS, NGA, OMN, PAK, QAT, SAU, SGP, TUN, TUR, USA, ZAF. All returned data on the check.

### Asset format

```json
{ "source": "World Bank WDI, FP.CPI.TOTL.ZG (Inflation, consumer prices, annual %), from IMF IFS. CC BY 4.0",
  "sourceLastUpdated": "2026-10-08",
  "generatedOn": "2026-10-16",
  "series": { "EGY": { "2024": "28.27", "2025": "14.07" }, "USA": { "2024": "2.95" } } }
```

- Values are **strings** (percent, 2 decimals as published rounding allows) → `Decimal.parse`. `null` years are omitted, so "as of" for a series = its last present year (US → 2024 today; AC-33 "assumed from" logic covers 2025+).
- Years 2000 onward (~26 years × 29 series ≈ 10 KB).
- Loaded once with `rootBundle.loadString` into `ShippedInflation` (core/assumptions) — no repository: it is read-only app content, not user data, and never moves to a server.

### Script

`dart run tool/gen_inflation.dart` — plain Dart, `package:http` (already a dependency), writes the file sorted and pretty so a regeneration diff is reviewable. Run by a human before a release; the commit message names the `lastupdated` date. Shipped values change only with an app update (story §8.1). The app never calls the World Bank (story §11).

### User override

Table `inflation_overrides(id, country, year, rate TEXT, created_at, updated_at)`, unique `(country, year)`. Lookup order for (country, year): override → shipped → latest earlier year from the merged view, marked "assumed from YEAR" → none ("series empty"). Because overrides are a separate table, an app update that ships a new shipped value can never overwrite a user value (AC-32); deleting the override row restores the shipped value.

## Why

**Problem:** owner decision Q3 — real returns must work from day one with no network, each value showing source and "as of" year, and the user may correct any year. A generated, versioned asset gives provenance in git, zero runtime network, and a one-command refresh.

## Rejected alternatives

- **World Bank + Eurostat HICP for the euro area** — the story's candidate pair; unnecessary since WDI publishes the `EMU` aggregate. Two scripts, two licences for no gain.
- **IMF WEO / IFS directly** — WEO mixes in projections (story forbids forecasts); IFS API needs more parsing for the same numbers WDI already republishes.
- **Hand-typed Dart const map** — no provenance, error-prone, untestable regeneration.
- **Seeding shipped values into the Drift DB** — mixes app content with user data and needs a migration on every update; the override-wins rule becomes a merge problem.
- **Online fetch at runtime** — out of scope (story §11).

## Trigger to revisit

- A supported country's last value is two or more years old at release time (WDI lag) → consider the national statistics office or IMF IFS for that country only.
- The euro-area aggregate disappears from WDI.
- A server phase: the server can serve fresher series.
